# Durable queue scaffold — not integrated

`src/running/queue.ts` is a pure injected-storage/injected-lock module. Browser use must supply actual cross-tab Web Locks; there is deliberately no unlocked fallback. No private payload is logged. It is account/incarnation scoped and starts paused, including after reload. Caller must verify auth and current incarnation; explicit recovery is required after ambiguous loss. No production or browser calls were made.

Mutations persist before optimistic success, remain immutable after enqueue, and carry a persisted attempted flag before network dispatch. Per-run locks serialize sending across tabs while account storage locks are short. Independent runs can send concurrently. New edits preserve earlier pending revisions. Acknowledgment requires correct IDs/revision/status/date/measurements/effort/notes/duration source. Failures retain separate retry/correction/conflict/auth/feature states. Explicit recovery moves auth/feature pauses to pending without changing IDs/payloads. Explicit local clear invalidates the local epoch before deleting storage so late responses cannot resurrect its data.

Tests exercise shared lock simulation, concurrent append/send, storage failure/corruption, reload without replay, account isolation, lost responses, persisted attempted flag, explicit recovery, malformed acknowledgments, auth pause and late-response handling. These tests do not prove real Web Locks or browser signout behavior.

Review corrections: a persistent clear-generation tombstone invalidates stale cross-tab writers and acknowledgments without retaining private payloads. Recovery captures both local epoch and shared generation and cannot override a newer pause/clear. Auth/feature failures pause memory before attempting fallible persistence. Failed clear remains paused and rejects without claiming storage cleared. Local validation includes contract UUID/Gregorian date rules, noncompleted null rules and finite normalized values. Fifteen queue tests and Kipp's two unchanged independent recovery/storage-error regressions passed; app TypeScript passed.

Before integration: actual Web Locks adapter and cross-tab UI pause signal, correction/conflict review with new mutation IDs and only never-sent successor rebasing, retry timing/backoff, visible queue status, all-action auth/feature error propagation, and every explicit signout/deletion path. Add run-zone future-date validation in logging UI and server remains authoritative. Ambiguous SDK signout versus expiry queue-retention policy still needs parent release review. The module must not be connected to a live replay controller until these gates pass.
